# 01. 対象プラットフォーム方針

## 結論

**モバイルファーストのレスポンシブ Web アプリ**として開発する。インストール不要で URL を開けばすぐ遊べることを最優先とし、PWA 対応によってアプリに近い体験も提供する。

## 選定理由

「隙間時間に遊ぶ」という利用シーンでは、以下が決め手になる。

- **起動までの手間ゼロ**: ストアからのインストールや登録が不要。ブックマークやホーム画面から 1 タップで起動できる
- **配布の手軽さ**: 静的ホスティング（GitHub Pages）に置くだけで全プラットフォームに届く。ストア審査・年会費が不要
- **開発効率**: 1 つのコードベースで PC・スマホ両対応。ミニゲームを「大量に」作る方針と相性が良い

## 対応環境

| 項目 | 方針 |
|---|---|
| 対応ブラウザ | Chrome / Edge / Safari / Firefox の最新版（いわゆるエバーグリーンブラウザ）。古いブラウザ対応のための polyfill は入れない |
| 画面サイズ | スマホ縦持ち（幅 375px〜）を基準にデザインし、タブレット・PC ではレイアウトを広げる |
| 入力 | タッチ操作を第一とする。牌の選択はタップ 1 回で完結させ、ドラッグ必須の操作は避ける |
| オフライン | PWA の Service Worker でアセットをキャッシュし、2 回目以降はオフラインでも遊べるようにする |

## モバイルファーストの実装指針

- 牌はタップしやすいサイズ（最低でも高さ 44px 程度のタップ領域）で表示する
- 手牌 13〜14 枚が横幅 375px に収まるよう、牌画像は縦横比を保ったまま可変サイズで描画する
- ホバー前提の UI（ツールチップ等）は使わず、タップで情報を出す
- 縦持ちで遊べることを基本とし、横持ちは必須にしない

## PWA 対応

`vite-plugin-pwa` を使い、以下を実現する。

- Web App Manifest によるホーム画面への追加（アイコン・スタンドアロン表示）
- Service Worker によるアセットのプリキャッシュ（オフラインプレイ）
- すべてのゲームデータ（何切る問題など）は静的ファイルとしてバンドルし、通信なしで完結させる

## 将来のアプリ化シナリオ

当面はストア公開しないが、後からネイティブアプリ化できるよう次の点を守って開発する。

1. **Web 標準 API のみを使う**: ブラウザ固有・OS 固有の API に依存しない
2. **ロジックと UI の分離**: 麻雀ロジック（`src/core/`）は DOM に依存しない純粋 TypeScript で書く（→ [04-architecture.md](04-architecture.md)）
3. **アプリ化の第一候補は Capacitor**: Web アプリをそのまま WebView でラップして iOS / Android アプリにできる。この構成なら追加コストが最小で済む

この方針を守っていれば「まず Web で公開 → 反応が良ければ Capacitor でストア展開」という段階的な移行が可能になる。
